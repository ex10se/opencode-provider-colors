# Reporting vulnerabilities

Do not publish tokens, keys, private session content, or complete user configurations in issues or logs.

If GitHub private vulnerability reporting is available, use it on the Security tab. Availability depends on repository settings; this document does not claim that it is enabled.

If there is no private channel, open an issue requesting one without exploitation details or sensitive data. Do not send secrets or reproduction material containing private data until a private channel has been agreed.

A safe initial report can include the package and OpenCode versions, the nature of the impact, and sanitized reproduction steps. If a secret is accidentally published, revoke or rotate it; deleting the message is not enough.

This policy does not guarantee a fix timeline or support for older versions.
