# opencode-provider-colors

[English](README.md)

Цвета фона и текста по провайдеру в TUI OpenCode. Для строк сессий, названий проектов и провайдеров можно задать RGB/RGBA или оставить штатный цвет отдельно для каждого поля.

## Установка

### Требования

- OpenCode 2.2.5 или 2.2.7 и возможность рендерера `rgb: true`. На других версиях интерфейс не меняется
- Для сборки нужны Node.js >=22.18.0 и npm
- Реализация зависит от внутренних компонентов UI, проверенных на OpenCode 2.2.5 и 2.2.7. Неизвестные и неоднозначные соответствия сохраняют штатное отображение
- Нативный проверочный стенд рассчитан на POSIX (macOS/Linux); это не утверждение о поддержке или отсутствии поддержки Windows самим плагином

### Пакет или исходники

Для установки версии 0.1.0 из npm в выбранный каталог:

```sh
npm install --prefix ./provider-colors opencode-provider-colors@0.1.0
```

В существующем `cli.json` укажите в поле `package` абсолютный путь к `provider-colors/node_modules/opencode-provider-colors`. Пример настроек ниже подходит и для установленного пакета. Сборка исходников при установке из npm не нужна.

В каталоге исходников:

```sh
npm ci --ignore-scripts
npm run build
pwd
```

Добавьте запись в существующий массив `plugins` файла `cli.json`. Замените путь на абсолютный каталог исходников из вывода `pwd`. Сохраните остальные настройки и плагины.

```json
{
  "plugins": [
    {
      "package": "/absolute/path/to/opencode-provider-colors",
      "options": {
        "providerColors": {
          "openai": {
            "bg": "#B8EEE41A",
            "activeBg": "#B8EEE40D",
            "hoverBg": "#B8EEE403",
            "sessionFg": null,
            "projectFg": null,
            "providerFg": "#B8EEE4"
          }
        }
      }
    }
  ]
}
```

Укажите каталог пакета, не `src` и не `dist/tui.js`. JSON не раскрывает `$PWD` и `~` автоматически. ESM-пакет экспортирует `opencode-provider-colors/tui` из `dist`. После изменения исходников повторите сборку; после установки или изменения настроек перезапустите TUI.

## Поведение

- Вне перетаскивания сохраняется штатный приоритет наведения, активной строки и раскрытого состояния
- Вне перетаскивания неактивные строки, требующие внимания, сохраняют штатный фон; заданные цвета текста сессии и проекта продолжают применяться
- Цвета не меняют модели, соединения с провайдерами, содержимое сессий или уведомления
- Оформление перетаскивания действует только на перетаскиваемую строку и имеет приоритет над наведением. После отпускания возвращается оформление текущего состояния

## Параметры

Ключи `providerColors` - точные ID провайдеров, не отображаемые имена. Имена реактивно поступают из реестра провайдеров SDK; плагин не создаёт и не переименовывает провайдеров.

В объектной палитре обязательно поле `bg`. Все цветовые поля принимают `#RRGGBB`, `#RRGGBBAA` или `null`:

| Поле | Назначение | Отсутствие / `null` |
| --- | --- | --- |
| `bg` | Фон обычной строки | Обязательно / штатный фон обычной строки |
| `activeBg` | Фон активной строки | Использовать `bg` / штатный активный фон |
| `hoverBg` | Фон при наведении | Использовать `bg` / штатный фон наведения |
| `sessionFg` | Название сессии | Штатный текст |
| `projectFg` | Название проекта | Штатный текст |
| `providerFg` | Название провайдера | Штатный текст |
| `dragBg` | Фон перетаскиваемой строки | Наследовать `activeBg` |
| `dragSessionFg` | Название перетаскиваемой сессии | Наследовать `sessionFg` |
| `dragProjectFg` | Проект перетаскиваемой сессии | Наследовать `projectFg` |

Альфа фона смешивает цвет со штатным фоном текущего состояния. Альфа текста применяется к итоговой ячейке с сохранением штатного затухания и свечения. Альфа `00` означает прозрачность, а не штатный текст; для штатного текста используйте `null`.

Единственный встроенный строковый цвет: `openai: "#B8EEE4"`. Остальные провайдеры сохраняют штатное оформление, пока для них явно не задана палитра. Настройки дополняют это значение: удаление записи `openai` возвращает цвет по умолчанию. Чтобы оставить штатные цвета для этого провайдера, задайте `null` во всех шести полях:

```json
{
  "providerColors": {
    "openai": {
      "bg": null,
      "activeBg": null,
      "hoverBg": null,
      "sessionFg": null,
      "projectFg": null,
      "providerFg": null
    }
  }
}
```

Провайдеры без палитры сохраняют штатные цвета. Старые записи `"provider-id": "#RRGGBB"` поддерживаются; восемь цифр доступны только в объектной форме. Старый параметр `providerRowOpacity` не меняет альфу объектной палитры. Подробности - в [справочнике](docs/configuration.md).

Отсутствие или `null` в drag-полях наследуют `activeBg`, `sessionFg` и `projectFg` соответственно. Отсутствующий `activeBg` наследует `bg`; явный `null` сохраняет штатный активный фон.

## Устранение неполадок

Если цветов нет, проверьте версию OpenCode, поддержку RGB, точный ID провайдера, корректность настроек, сборку и путь к пакету. После изменения настроек перезапустите TUI. Штатное отображение может быть намеренным защитным поведением; см. [проверки](docs/verification.md).

## Ограничения

- Поддерживаются только OpenCode 2.2.5 и 2.2.7 с RGB; это не диапазон версий
- При повторяющихся названиях и неоднозначном соответствии провайдера строке используется штатное отображение
- Некорректная палитра или настройка прозрачности оставляет плагин неактивным
- Нативные UI-проверки рассчитаны на POSIX; поддержка Windows не установлена
- Сценарий перетаскивания не проверяет отмену клавишей Escape

## Проектные решения

Плагин сохраняет штатное отображение, когда строку нельзя однозначно определить, использует точные ID провайдеров с реактивными именами SDK и различает прозрачный и штатный цвет. Подробности - в [решениях и компромиссах](docs/design.md).

## Разработка

Предварительно установите Node.js >=22.18.0, npm и Bun 1.4.4, затем выполните `npm ci --ignore-scripts`. CI проверяет Node.js 22.19.0 и 24 с этой закреплённой версией Bun. `npm test` включает runtime-тест, запускающий Bun с browser conditions для Solid.

SDK OpenCode - только dev-зависимость, закреплённая на 2.2.5. Используемый API также проверен на настоящем OpenCode 2.2.7. Установка пакета в consumer не устанавливает SDK или OpenTUI. Поддерживаемые версии хоста: 2.2.5 и 2.2.7. Регрессионные тесты зависимостей проверяют корневой dev-граф. Корневой `npm audit` и audit изолированного consumer внутри package smoke-теста - отдельные проверки.

```sh
npm test
npm run test:dependencies
npm run typecheck
npm run build
bun test/native/core-081.ts
node test/package-smoke.mjs
npm audit --audit-level=moderate
npm pack --dry-run
```

Это команды проверки, а не утверждение об их успешном прохождении в текущей копии. Package smoke-тест создаёт и устанавливает локальный tarball в изолированное временное окружение и требует доступа к публичному npm registry. OpenTUI core probe не запускает OpenCode. Для полного нативного UI-стенда нужны отдельно предоставленный исполняемый файл OpenCode 2.2.5 или 2.2.7 и Python 3 со стандартной библиотекой на POSIX; в CI этот стенд не запускается. Команды, проверенные окружения и границы проверки приведены в [матрице](docs/verification.md).
